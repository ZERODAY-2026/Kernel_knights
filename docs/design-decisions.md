# Key Architecture & Design Decisions

This document summarizes the primary technical decisions made during the architecture of the **Private Legal Document Triage Agent**, along with alternatives considered, technical justifications, and associated trade-offs.

---

## Decision Matrix

| # | Design Decision | Alternatives Considered | Selection Rationale | Trade-off / Consequence |
| :- | :--- | :--- | :--- | :--- |
| **D1** | **Local Gemma 4 via Ollama** | Cloud APIs (OpenAI GPT-4o, Anthropic Claude, Google Gemini API) | **Absolute privacy**. Sensitive legal agreements (leases, offer letters) must never be transmitted across the public internet. Local execution provides an airtight privacy guarantee. | Slower inference speed compared to cloud clusters; requires local hardware with at least 8–16 GB RAM. |
| **D2** | **Lexical TF-IDF + 5-char Stemmer for Q&A** | Dense Vector Embeddings with Vector Database (ChromaDB, FAISS, LangChain) | **Zero-overhead, minimal RAM footprint**. Avoids loading a second embedding model (e.g. MiniLM) into memory alongside Gemma. Prefix stemming handles common legal derivations (`sublet` ~ `sublease`, `terminat` ~ `termination`). | Semantic synonyms without shared stems (e.g., "canine" for "dog") are not matched; relies on lexical keyword overlap. |
| **D3** | **Deterministic Code-Level Verbatim Quote Verification** | LLM self-reflection ("Did you quote accurately?") | **Anti-hallucination guarantee**. LLMs frequently hallucinate or slightly alter quotes. Deterministic Python substring matching guarantees that only verbatim text from the source contract can be presented as evidence. | Quotes shorter than 8 characters are dropped to prevent trivial matches; slight OCR errors or character variations cause quotes to be dropped. |
| **D4** | **Deterministic Refusal for Legal Verdicts** | Prompt instructions asking the LLM to refuse enforceability queries | **Unbreakable safety boundary**. Prompt-based refusals can be bypassed with adversarial jailbreaks. Deterministic regex intercepts verdict questions (`VERDICT` pattern) before the model is ever called. | Rigid pattern matching; unconventional rephrasings of enforceability questions might bypass regex to the model prompt layer. |
| **D5** | **Zero-External-Dependency Single-File Frontend** | React, Next.js, Vue, Tailwind CSS via CDN | **Enforces strict Content-Security-Policy (CSP)**. A single HTML/CSS/JS file requires no build step (`npm run build`), no Node.js runtime, and zero external network requests for CSS, JS, or fonts. | More verbose vanilla JavaScript and CSS; lacks reactive component framework ergonomics. |
| **D6** | **Ephemeral Temp File with Immediate Deletion** | In-memory `io.BytesIO` streams only | `pypdf.PdfReader` performs most robustly with seekable file descriptors. Creating a temporary file that is unlinked immediately in a `finally` block ensures high compatibility with zero residual disk storage. | File briefly touches local storage for milliseconds before extraction; mitigated by unlinking in `finally` block. |
| **D7** | **Pypdf Ingestion without PyMuPDF or OCR** | PyMuPDF (fitz) or Tesseract OCR | **Clean licensing and minimal footprint**. PyMuPDF is under the restrictive GNU AGPL license, and OCR engines add significant binary weight (100MB+) and complex system dependencies. `pypdf` is lightweight and permissively licensed (BSD). | Scanned image PDFs without native text streams cannot be parsed and are rejected. |
| **D8** | **Document Silence Gate (< 30% Coverage)** | Always querying the LLM and instructing it to say "I don't know" | **Prevents conversational hallucination**. When a topic is completely absent from a contract, feeding the entire document to an LLM frequently results in subtle confabulation. Hard cutoff at 30% lexical coverage avoids calling the model entirely. | If a question is phrased with obscure terminology, the system may classify it as silent even if a related general clause exists. |
| **D9** | **Schema Enforcement via Pydantic (`format=json`)** | Free-form markdown generation with post-hoc parsing | **Structured UI rendering**. Guaranteeing that the model responds strictly according to the `ClauseAnalysis` and `QAAnswer` schemas ensures reliable UI cards, badges, and status indicators without fragile regex extraction. | Gemma 4 must support structured schema outputs; occasionally requires a retry if Ollama fails to enforce schema. |
